# SpectrMind Telegram Bot

Бот для автоматической генерации и публикации постов о нейронауке, нейропсихологии и здоровье в Telegram-канал SpectrMind.

## Возможности

- 9 рубрик: протоколы, разборы мифов, исследования, утро, вечер, опросы + оффтоп-линия (разборы БАДов, новости здоровья, загадки мозга)
- Живой авторский тон вместо шаблонных текстов: правила голоса вынесены в `content/style_guide.py`
- Автопостинг 1 раз в день по расписанию, рубрика выбирается из ротации без повторов тем
- Опросы публикуются нативными опросами Telegram — с кнопками ответов, а не текстом
- CTA с кнопками покупки: раз в N постов пост ведёт в бота `@spectrnewsbot`
- Автоматические хештеги под каждую рубрику
- Fallback-цепочка моделей и повторы при обрыве или пересказе штампами
- Проверка состояния моделей прямо из Telegram: `/diagnose`

## Быстрый старт

### 1. Создай бота

Открой [@BotFather](https://t.me/BotFather) в Telegram:
```
/newbot
Имя: SpectrMind Content Bot
Username: spectrmind_content_bot
```
Сохрани токен.

### 2. Получи API-ключ OpenRouter

Зарегистрируйся на [openrouter.ai](https://openrouter.ai):
1. Перейди в Settings → API Keys
2. Создай ключ
3. Сохрани ключ

### 3. Узнай ID канала

1. Добавь бота админом в канал SpectrMind
2. Перес любое сообщение из канала боту [@userinfobot](https://t.me/userinfobot)
3. Скопируй числовой ID (например `-1001234567890`)

### 4. Настрой окружение

```bash
cp .env.example .env
```

Заполни `.env`:
```
BOT_TOKEN=123456:ABC-DEF...
OPENROUTER_API_KEY=sk-or-v1-...
CHANNEL_ID=@spectrmind
ADMIN_ID=123456789
```

### 5. Установи зависимости и запусти

```bash
pip install -r requirements.txt
python bot.py
```

## Команды бота

| Команда | Описание |
|---|---|
| `/start` | Приветствие |
| `/generate` | Сгенерировать пост (превью) |
| `/generate бады` | Сгенерировать конкретную рубрику |
| `/post` | Опубликовать в канал (админ) |
| `/post миф` | Опубликовать конкретную рубрику |
| `/types` | Список рубрик и псевдонимов |
| `/schedule` | Текущее расписание |
| `/diagnose` | Проверить прокси и доступные модели (админ) |
| `/help` | Справка |

Команды с типом принимают и ключ (`supplement_recap`), и русский псевдоним (`бады`, `новости`, `загадка`, `миф`, `протокол`, `утро`, `вечер`, `опрос`).

| Ключ | Эмодзи | Описание | Вес |
|---|---|---|---|
| `micro_protocol` | ⚙️ | Микро-протокол | 5 |
| `myth_buster` | ❌ | Разбор мифа | 4 |

| `morning_routine` | ☀️ | Утренний протокол | 3 |
| `evening_reflection` | 🌙 | Вечерний совет | 2 |

В утреннем слоте `micro_protocol` и `morning_routine` получают двойной вес, остальные рубрики остаются в ротации — поэтому оффтоп выпадает регулярно, но не каждый день.

## Опросы

Рубрика `poll` публикуется **нативным опросом Telegram**: `send_poll` с вопросом и вариантами ответа, у подписчика появляются кнопки голосования. Модель просят выдать структуру «ВОПРОС: … ВАРИАНТЫ: …», бот её разбирает и проверяет: не меньше двух вариантов, варианты короткие и без маркеров списка. Если ответ не подходит — повтор, потом следующая модель.

Текстовый пост с вариантами «строками ниже» выглядит как опрос, но кнопок не имеет — именно эта ошибка была раньше.

## CTA и продажи

Каждый `CTA_EVERY_N_POSTS`-й пост (по умолчанию каждый 3-й, то есть раз в 3 дня при одном посте в день) получает:

- текст-CTA с болью читателя и предложением 21-дневного протокола;
- кнопку **«🧠 21-дневный протокол»**, ведущую в бота `@spectrnewsbot`, где лежат бесплатный гайд и оплата.

Обычные посты уходят **без кнопок вообще**: подписчики уже в канале, звать их туда смысла нет. Кнопка на бесплатный канал включается отдельно через `SHOW_CHANNEL_BUTTON=true` — она нужна только если пост продвигается вне канала.

Тексты CTA хранятся в `config.CTA_VARIANTS` и чередуются, чтобы не приедались. Если нужны кнопки с прямыми ссылками на оплату, задайте `PAID_CHANNEL_LINK`, `NEUROGUIDE_LINK`, цены и включите `SHOW_DIRECT_PAY_BUTTONS=true`.

Основной путь покупки — через бота, поэтому прямые платёжные ссылки по умолчанию выключены.

## Тестовый пост при перезапуске

По умолчанию **выключен** (`STARTUP_POST=false`): перезапуск сервиса не должен присылать подписчикам лишнее сообщение. Включить для разовой проверки:

```bash
STARTUP_POST=true
```

Такой пост уходит чистым контентом — без CTA и без кнопок.

## Человечный тон: как это устроено

Правила голоса лежат в `content/style_guide.py` и подставляются во все промпты:

- тон «умный друг на ты»: хук вместо разгона, конкретика вместо общих слов, честность про слабые эффекты
- список запрещённых штампов и канцелярита («в современном мире», «важно отметить», «является» и т. п.)
- запрет markdown (бот публикует с `parse_mode=None`, поэтому разметка попала бы в канал как символы)
- ограничения на медицинскую лексику: без диагнозов, лечения и дозировок

После генерации текст проходит проверку: обрыв по длине, наличие штампов, длину по рубрике. Если модель обрывается или пересказывает шаблонами, бот делает повтор и только потом переходит к следующей модели. Хештеги подставляются автоматически под рубрику, а не берутся из ответа модели.

Рубрика `supplement_recap` специально написана как научный обзор: разбирается доказательная база добавки, без доз, схем приёма и советов «пропейте курс». Тематическая база — в `content/topic_pool.py`.

## Диагностика

Проверка без запуска бота:

```bash
python3 tools_check_models.py    # какие модели отвечают через ваш прокси
python3 tools_check_models.py --free                    # какие бесплатные есть сейчас
python3 tools_check_models.py --pricing model/a,model/b # цены за миллион токенов
python3 tools_selfcheck.py       # логика промптов и генерации, офлайн
python3 tools_check_pyver.py     # несовместимости с Python на сервере
python3 tools_check_runtime.py   # импортируются ли все модули
```

`tools_selfcheck.py` не ходит в сеть: он подменяет вызов OpenRouter и проверяет ротацию рубрик, чистку текста, пороги длины, детектор штампов, подстановку хештегов, разбор опросов, кнопки CTA и поведение на битых ответах API.

`tools_check_pyver.py` ищет то, что работает на новом Python, но ломает старый на сервере: обратный слэш внутри f-строки (3.12+) и `X | None` в аннотациях, которые вычисляются при импорте (на 3.9 это `TypeError`). `tools_check_runtime.py` дополнительно реально импортирует все модули процесса — на самой машине.

Внутри Telegram то же самое показывает `/diagnose` — если ни одна модель не отвечает, проблема почти всегда в прокси (`PROXY_URL`) или в имени модели.

## Требования к Python

Проект совместим с **Python 3.8** и новее (сервер работает на 3.8). Если локальный Python свежее серверного, перед деплоем запустите:

```bash
python3 tools_preflight.py          # все проверки разом
```

По отдельности:

```bash
ruff check --target-version py38 .
python3 tools_check_pyver.py --target 3.8
python3 tools_check_runtime.py
```

Файлы, где аннотации используют синтаксис новых версий, начинаются с `from __future__ import annotations` — это делает аннотации ленивыми и снимает проблему.

Чтобы проверки запускались автоматически перед каждым пушем, включите хук один раз:

```bash
git config core.hooksPath .githooks
```
